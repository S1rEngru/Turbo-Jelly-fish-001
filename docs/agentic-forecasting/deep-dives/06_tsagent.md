# 金融训练 TS-Agent：优先参考已有训练脚本的受控改进

查阅日期：2026-09-17。这里指 Yihao Ang 等人的《Structured Agentic Workflows for Financial Time-Series Modeling with LLMs and Reflective Feedback》，arXiv:2508.13915v1。不是同名的时序推理 Agent。**本次未确认官方可运行开源仓库，保留为方法参考。**

## 1、背景

论文从已有代码管线和领域知识出发，让 Agent 完善和改进训练模板；任务包括金融时序预测与生成。[论文 v1](https://arxiv.org/html/2508.13915v1)

**入选理由（本项目分析）**：这与“已经有 baseline，但换品牌需要手动适配”的工作形态很接近。值得借鉴的重点是如何限制改动范围，而不是金融领域本身。

## 2、问题

作者设置了训练模板 `train.py`、案例库、改进知识库，以及模型和指标代码库，让 Agent 利用这些资源完成实验。[论文 v1，第 3 节](https://arxiv.org/html/2508.13915v1)

**映射到本项目**：现有脚本包含经过人验证的经验，应先识别哪些部分固定、哪些部分可配置。把全部代码交给 Agent 重写，会丢失这类经验，也难以判断效果变化的原因。

## 3、难点

**本项目分析**：最重要的是如何定义“允许改什么”。

- 模型与参数可以探索，销量口径和品牌范围不能在实验过程中悄悄变化。
- 同一组超参数可能只适合某种数据长度，案例复用必须带有适用条件。
- 一个训练报错与一次准确率下降不是同一类反馈，应分别处理。
- 训练耗时可能远高于语言模型调用耗时，搜索预算需要覆盖模型训练。

另有需要注意的原文口径：论文对目标和反馈使用了 test dataset 等表述。因此本次不能将其评估流程直接认定为完全隔离测试反馈的模板。[论文 v1，第 3.2 节](https://arxiv.org/html/2508.13915v1)

## 4、实现方法

### 论文中的机制

方法先做候选模型的短训练预选，再围绕保留候选迭代细化，结合训练结果与知识资源调整脚本。[论文 v1，第 4 节](https://arxiv.org/html/2508.13915v1)

### 如何借鉴（以下均为本项目建议）

可以给 baseline 外围增加配置层：

| 固定部分 | 可探索部分 |
|---|---|
| 数据版本与目标定义 | 模型候选 |
| 时间切分、最终留出集 | 回看窗口与训练步数候选 |
| 评分函数和预测长度 | 学习率、批大小等范围 |
| 产物格式和运行日志 | 明确允许的特征组合 |

实验分两阶段：先以较小预算检查候选是否值得继续，再对少量候选投入完整预算。但不能把短训练排名当作最终排名：某些模型收敛更慢，需要保留探索名额或允许重新评估。

知识库也需要从真实项目经验积累。每条经验至少记录适用条件、证据来源、成功和失败案例。例如“短历史品牌通常先试较小模型”只能作为候选建议，不能自动排除其他模型。不同品牌可共享经验，但不能共享未来时间段的信息。

每轮实验记录配置、变更、运行结果和保留／拒绝理由；下一轮读取的是这张结构化表，而不是无限增长的聊天记录。最后保留没有改善的实验，避免未来再次消耗相同预算。

## 5、效果

论文股票实验表中，GPT-4o 驱动的 TS-Agent 的 MAE 为 4.912，AutoGluon 为 5.258；该行 TS-Agent 成功率为 100%。作者报告实验结果取五次运行均值。[论文 v1，实验与表 1](https://arxiv.org/html/2508.13915v1)

根据这两个 MAE 数值计算，相对下降约 **6.58%**，计算式为 `(5.258 - 4.912) / 5.258`。这是本次对表中一个设置的计算，不是跨数据集平均收益，也不是统计显著性结论。

这项研究值得作为“围绕已有训练管线做 Agent”的可行性线索。金融数据上的结果不能证明它能处理零售促销、缺货、新品或跨品牌迁移；缺少已确认代码入口也限制了即时复现。

本项目后续最公平的测试是：给原 baseline 的普通调参与 Agent 相同的训练预算，观察是否节省人工并稳定改进新品牌的留出表现。只有在这些任务上证实改进，才能讨论是否进一步训练 Agent 策略。
