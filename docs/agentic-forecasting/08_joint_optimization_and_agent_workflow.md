# 模型、特征、超参联合优化：代码调研与方案映射

调研日期：2026-09-18。范围：研究设计，不实现企业脚本。来源优先级：仓库实际代码 > 论文 > 宣传性文档。以下链接指向可变的 main 分支，未锁定 commit，不能视为不可变的复现实验快照。

## 结论

当前最贴合的组合是 RD-Agent 的实验闭环 + FLAML 的成本敏感搜索 + 基于缓存预测的精确子集评估。没有核实到一个开源项目已经完整实现用户所需的 NeuralForecast、财务月修复、特征选择、超参搜索与等权组合联合优化。这里给出的是组件级证据及据此提出的设计，不是现成产品能力宣称。

## 业务问题的形式化

用户已确认：四个模型，15 个非空子集，日预测等权平均；static/future/history 特征可配置；解释器提供特征贡献；超参尚由人工调整；异常数据由历史预测生成参考序列后与事实加权。财务月 horizon 28–35，按时间扩展训练。

应区分模型家族选择、每个家族的训练配置、最终预测组合。一个训练候选 c=(模型m,特征F,超参theta,数据/修复版本,切分,随机种子,训练预算)。候选生成日预测后存入档案 P。最终优化对象为组合业务分数 V(mean(P_S))，S 是候选子集。示意公式中的 V 方向取决于脚本；若越小越好则最小化。

共享特征配置发生变化通常需要重新训练所有受影响模型；单个模型特有配置变化只重训对应模型。共享神经网络内部不同组织/品牌不等于可独立重训的参数块。

反复用于决策的 test value 实质成为开发/验证分数，需要另留按时间隔离的最终测试。所有候选使用一致滚动切分、真实值、聚合方式；修复后的训练目标不能替换真实验证目标。

## 代码证据

### RD-Agent：决策、规划、动作闭环

源文件 quant.py 中 QuantRDLoop 通过 hypothesis.action 将实验生成、coding、running、feedback 分发给 factor 或 model 分支。运行错误能转换为 decision=False 的反馈。它是可追踪的实验闭环；不是销售预测专用管线。

quant_proposal.py 的 prepare_context 提供 bandit、llm、random 三种动作选择；model 提示明确允许保留模型、只改训练或模型超参。它按动作筛选历史，并引入另一类已接受实验的信息。这说明特征和模型可交替优化，而不是永远分离。

bandit.py 的 LinearThompsonTwoArm 只有 factor/model 两个动作，EnvController 使用金融指标向量的加权值作为 reward。此处没有 GPU 时间或训练费用项，也不是相对基线的改善量。金融回测的 with_cost 不代表模型训练计算成本。该实现可参考动作路由，但不能直接宣称解决了成本敏感的联合搜索。代码也没有证明该策略优于简单轮转。

- https://github.com/microsoft/RD-Agent/blob/main/rdagent/app/qlib_rd_loop/quant.py
- https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/proposal/quant_proposal.py
- https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/proposal/bandit.py

### FLAML：搜索空间与成本调度

blendsearch.py 的 BlendSearch 支持低成本初始配置、类别成本信息、历史起点、成本字段和预算。_select_thread 使用剩余预算、搜索线程的改进速度及 estimated cost for improvement 更新优先级；_should_skip 避免已知配置重复评估。它不是让 LLM 随口给参数。

接口层面的注意事项：lexico_objectives 在该文件中注明仅 CFO 支持；指标约束的惩罚机制不等于所有建议天然可行；需要终选检查。配置去重也不自动提供 NeuralForecast 预测文件缓存或断点续训，需要适配层。

来源：https://github.com/microsoft/FLAML/blob/main/flaml/tune/searcher/blendsearch.py

### TSci：编排例子，不是联合优化算法

TimeSeriesAgentGraph._build_graph 明确连接 preprocess → analyze → validate → forecast → report → END。可以学状态传递和职责拆分，但图本身没有反馈回路，也没有训练成本调度。不能因其使用 LangGraph，就认定已经实现本任务中的自适应联合优化。此前文档记录的预测失败分支使用测试真实值统计量的问题仍需保留。

来源：https://github.com/Y-Research-SBU/TimeSeriesScientist/blob/main/time_series_agent/graph/agent_graph.py

### NeuralForecast：执行后端

Auto 模型的通用逻辑位于 _base_auto.py。现有 Auto 的单模型验证损失与用户完整的多模型组合业务 value 不相同，因此本方案需要在其外部评价候选组合。不要将跨配置优化默认理解成训练权重共享。

## 建议的 Agent 工作流（本研究提出，非上述项目原样功能）

状态记录：当前最好方案、候选预测档案、滚动评估分项、归因摘要、尝试历史、运行失败、已用预算和估计成本。

决策：选择本轮改特征、局部调参、探索模型，或结束。LLM 可以结合残差和业务知识提出假设；预算检查、可用参数和接受规则由程序约束。

规划：每次输出结构化实验单，包含假设、parent 配置、改动范围、候选空间、滚动切分、筛选预算、完整复核条件、停止规则。已有成熟脚本时优先调用固定工具，不必让 Agent 每次重写训练代码。

动作：validate_config、train_candidate、predict_folds、evaluate_business_metrics、select_ensemble、record_experiment 等接口。名称为建议接口，不是已存在的企业代码。

反馈：记录实际耗时、单模型分数、组合增量、各 AP/组织层级表现、是否满足约束。接受规则应由预先确定的指标决定，LLM 负责解释和下一步假设。

闭环：
读取状态 → 提出实验 → 检查预算/配置 → 复用或执行 → 重算组合 → 评价/归档 → 下一轮或停止。

## 联合优化：分层、交替、保留少量联合探索

不推荐一次性“筛特征 → 调超参 → 选组合”后永不回头。特征改变会改变最佳超参；单模型变好也可能让组合更差。

1. 原配置跑四个基线，缓存各滚动折日预测；精确比较15个子集。
2. 按业务语义对特征分组，用归因和残差提出少量消融假设。归因不是删列后的性能收益，相关特征应考虑成组消融。
3. 固定一个模型和特征方案，给 FLAML/其他搜索器一个局部条件空间及成本预算。
4. 每获得新预测，重新评价其对组合的边际贡献，而非只看单模型排名。
5. 保留有限的多样性候选，定期跨特征方案或模型重新探索，避免交替优化停在局部最优。
6. 入围方案完整滚动复核；最后只使用未参与选择的测试期报告泛化结果。

模型家族决定合法超参，特征选择可以编码为分组布尔变量。并非所有模型必须共享一组超参。若允许每个模型有不同特征，候选空间更大，但成本可以隔离；若企业接口要求统一特征，需将其视为一个会触发多模型重训的昂贵动作。

四个预测候选时始终只有15个非空组合；若保留同一家族的多个版本，候选数K增加，组合数变为2^K-1，必须限池、限制每家族版本，或改用贪心/束搜索。不能持续声称仍只有15种。

组合感知的局部搜索：固定参考候选池 P_ref，在一批搜索中评价新增候选后最好组合的提升。若每个 trial 随时变更参考池，同一配置的目标会漂移，优化器历史失去可比性。应固定一批内的参考池，更新后启动下一批或重新计算缓存候选目标。候选单体原始分数和预测始终保留。

这种做法不是全局最优保证。少量联合探索用于补偿块坐标优化可能遗漏的交互；验证预算不足时应优先减少可调维度。

## 成本控制

组合重算只需预测缓存，通常远低于训练成本。归因可能需要反向传播或大量模型调用，也必须计时。删特征、改网络结构通常触发重训；新增模型含适配与训练成本。

建议记录每次实验的实际 GPU/CPU 时间、失败耗时及并发资源，第一版使用预算配额和实测成本；有足够记录后再研究上下文 bandit。预计改善/成本可以作为调度启发式，但不能冒充可靠的已知收益；需要保留探索预算，避免便宜动作耗尽机会。

低预算筛选可少训练步数或减少开发折，但时间序列不能随机打乱验证。低预算排序可能偏向快收敛模型，因此入围项必须在一致完整预算下复核。提前停止、权重热启动、完整断点续训是不同机制，不能混称部分重训。

缓存键应覆盖原数据/修复版本、时间切分、特征及预处理、模型超参、种子、代码版本和训练预算。否则同名配置可能错误复用。

## 异常财务月处理

这是相对当前冻结数据版本的一次性动作，而非跨所有未来月份只运行一次。历史回测的每个起点必须只使用当时可见数据完成异常识别和修复。四模型生成反事实本身也有训练成本。

建议以走步预测残差而非绝对销售额判断异常，同时考察月累计偏差、日异常比例、持续性和组织影响范围；用更早月份残差分布估计稳健尺度/分位阈值。阈值通过历史回测在误修正常月份与下游预测收益间校准，没有通用最优3-sigma规则。

销售异常可能是真实活动、制度变化或永久性变化，不能默认抹平。已有加权修复中的参考序列只是模型预测基线，不自动拥有因果反事实含义。

在一次1/2/3搜索期间冻结异常标记和 repair 权重，保证比较口径稳定；如果以后搜索 repair 权重，则把它作为更外层的数据处理配置，重新生成对应缓存和训练结果。最终评价保留原始实际销售额。
